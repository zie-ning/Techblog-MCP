## M1에서 넘어온 항목

근거가 된 실사용 테스트 기록은 [M1 사용 피드백](M1.md#사용-피드백)에 있다.

- **README 안내**
  - MCP prompt(`/techblog`)는 지원하는 클라이언트에서만 동작한다. Claude Code CLI는 동작, Claude 데스크톱 앱(Code 탭)은 "사용할 수 없는 명령어"로 실행되지 않음 (시나리오 9)
  - 도구 호출마다 허용 창이 뜨므로 "항상 허용" 안내 (시나리오 1)
- **서버 기동 시간**: M1 기준 시작 → initialize 응답 1.4~1.9초. 세션을 열자마자 질문하면 첫 질문에서는 서버가 없는 것과 같음 (시나리오 6). `uvx` 배포 형태로 다시 재고, 구간별(uv 환경 확인, import 등)로 나눠 단축 검토

## M4에서 넘어온 항목

- **검색 DB 크기**: 전체 추출 뒤 `data/techblog.sqlite` 8.3MB(1,315개 항목), `data/entries.jsonl` 5.1MB. DB 전달 방법(패키지 포함, Release 다운로드, 설치 시 빌드)을 정할 때 기준 값으로 쓴다. M5 뒤 문서 확장 열이 들어가 DB는 9.3MB, 설치 시 빌드한다면 `data/expansions.jsonl` 1.1MB도 필요하다

## M5에서 넘어온 항목

- **첫 검색 지연**: M5 뒤 첫 `search`가 약 3초(Kiwi 로딩 + 사용자 사전 등록 + 관련도 기준 계산), 이후 검색은 0.05초(Windows, 로컬 측정). 기동 시간을 재고할 때 함께 본다
- **도구 설명 확정**: `search`에서 `limit`이 없어졌고, 설명에 "한 주제의 짧은 명사구로, 여러 하위 주제는 나눠 검색"이 들어갔다. `aggregate` 설명에는 "기술별 집계는 같은 계열을 합친다"가 들어갔다. README 지시문 스니펫과 어긋나지 않게 한다
- **README 안내**: 검색은 단어 일치(뜻으로 찾지 않음)라는 한계와, 결과가 없으면 검색어를 나누거나 표기를 바꿔 다시 찾으라는 안내

## 진행 기록

### 기동 시간과 첫 검색 지연 (2026-10-04, Windows 로컬)

서버를 stdio로 띄워 initialize 응답, 첫 `search`, 다음 `search` 시간을 쟀다. 측정 스크립트는 임시로 쓰고 저장소에 두지 않았다.

**구간별 (같은 프로세스에서 순서대로)**

| 구간 | 시간 | 비고 |
| --- | --- | --- |
| `mcp` import | 1.3~2.0초 | SDK 내부(타입 정의, starlette·uvicorn). 우리 쪽에서 줄이기 어려움 |
| `techblog_mcp.server` import, DB 연결 | 0.1초 | |
| Kiwi 생성 + 사용자 사전 | 0.9~1.5초 | |
| 사용자 사전을 넣은 뒤 첫 분석 | 1.5~2.4초 | 사전을 넣으면 첫 분석에서 추가 준비가 일어남 |
| 이후 검색 | 0.01~0.08초 | |

**변경 전후 (`uv run techblog-mcp`, DB 있음)**

| | initialize | 첫 search | 비고 |
| --- | --- | --- | --- |
| 변경 전 | 1.8~2.1초 | 2.5~3.5초 | 첫 호출 때 Kiwi를 불러와서 언제 검색해도 같음 |
| 변경 후, initialize 직후 검색 | 1.5~1.6초 | 2.5초 | 미리 준비 중이라 기다림 |
| 변경 후, 1초 뒤 검색 | 1.6초 | 1.6~1.8초 | |
| 변경 후, 2초 뒤 검색 | 1.6초 | 0.7~1.0초 | |
| 변경 후, 3초 뒤 검색 | 1.6~1.7초 | 0.02~0.05초 | 세션을 열고 질문을 입력하는 동안 준비가 끝남 |

- 백그라운드 준비가 initialize 응답을 늦추지 않았다.
- `uvx --from <경로>`로 실행하면 initialize가 2.4~2.8초로 `uv run`보다 약 1초 느리다(uvx 환경 확인). 처음 설치할 때는 패키지 설치로 initialize까지 약 14초 걸리지만 한 번뿐이다.
- **첫 실행(DB 다운로드)**: 빈 캐시에서 initialize 직후 검색하면 첫 결과까지 7~13초. 다운로드(9.3MB, GitHub CDN 4~10초, 네트워크에 따라 다름)와 Kiwi 준비를 동시에 해서 둘 중 긴 쪽만큼 걸린다. 한 번뿐이다.
- **검토했지만 쓰지 않은 것**: Kiwi의 다중어 사전을 끄면(`load_multi_dict=False`) 생성 + 첫 분석이 2.5초에서 1.3초로 준다. 하지만 토큰이 달라지는 항목이 생겨(300개 중 5개) 색인 재빌드, `SCHEMA_VERSION` 변경, 검색 평가 재실행, 새 DB 배포가 필요하다. 백그라운드 준비로 이미 첫 질문 전에 끝나는 경우가 대부분이라 쓰지 않았다. 오타 사전 끄기와 `num_workers=0`은 시간 차이가 없었다.
- DB가 없거나 내려받지 못하면 도구 결과로 이유를 알린다. 이 예외는 MCP SDK가 "예상치 못한 오류"로 보고 스택 트레이스를 남기기 때문에 `ToolError`로 바꿔 메시지만 돌려준다.

### 도구 설명 확정과 기술 필터 계열 펼치기 (2026-10-05)

M1 실사용 기록과 실제 결과 형식을 보고 고쳤다. 설명 전문은 `src/techblog_mcp/server.py`가 기준이다.

| 도구 | 추가한 안내 | 근거 |
| --- | --- | --- |
| `get_details` | 본문 줄은 요약, "근거"는 원문 그대로인 문장(검증됨). 원문 표현은 근거 문장으로 인용 | 요약을 원문 표현처럼 인용하지 않게 |
| `get_details` | 원문 전체가 아니라 요약과 짧은 발췌뿐. 결과에 없는 세부는 원문 링크로 안내 | M1 시나리오 1(열지 않은 내용을 자기 지식으로 채움), 저작권 방침 |
| `get_details` | 같은 글의 다른 항목은 질문과 관련 있어 보일 때 이어서 열기 | M1 시나리오 2(관련 항목 case_0025를 열지 않음) |
| `aggregate` | 건수는 8개사 블로그에 글로 쓴 사례 수이지 실제 도입 현황이나 업계 전체가 아님 | 질문 예시가 도입 현황처럼 읽힘. M1 시나리오 4에서는 에이전트가 스스로 한계를 밝힘 |
| `aggregate` | 검색어로는 집계할 수 없고 필터로만 범위를 좁힘. 필터로 표현되지 않는 주제는 `search` | 검색어로 집계하려다 헤매지 않게 |

- **기술 필터 계열 펼치기** (사용자 결정, [기획.md](../기획.md)): "Kafka"로 거르면 하위 기술(Amazon MSK, Kafka Connect, Kafka Streams, ksqlDB)까지 찾아 141건이 된다. 계열 합산 집계(141건)와 같다. 이전에는 132건이라 같은 Kafka인데 숫자가 달랐다. 검색 평가셋은 변경 전후 지표가 같았다(기술 필터 질문 Kafka·Iceberg 포함, Recall@5 0.615, MRR 0.920).
