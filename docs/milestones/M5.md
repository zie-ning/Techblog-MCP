# M5. 검색 평가와 튜닝

> 상태: **대기** (관찰 기록은 M1부터 누적 중) · 허브: [docs/README.md](../README.md)

## 작업

- 검색 평가셋 30개 작성 (질문 + 정답 항목)
- Recall@5, MRR 측정 → 검색 필드 가중치 조정, "결과가 적다" 기준 결정
- **`search` 결과 수 결정 구현**: `limit` 파라미터 제거, 관련도 기준을 넘는 항목만 최대 10건 반환 (결정 배경은 [기획.md](../기획.md) "결과 수 결정"). 기준은 아래 관찰 기록과 평가셋 수치로 정함
- **하이브리드 검색 실험(필수)**: 로컬 임베딩 + BM25 결합을 BM25 단독과 비교. 도입 여부는 수치와 설치 부담(패키지 크기, 시작 시간)을 함께 보고 결정. 단어는 겹치지만 뜻이 다른 글(예: "선착순 동시성" 검색에 "멤버십 대량 일괄 발급" 글이 2위)을 구분하는지 확인

## 완료 기준

평가 수치와 결정 근거 기록

## M1에서 넘어온 과제

근거가 된 실사용 테스트 기록은 [M1 사용 피드백](M1.md#사용-피드백)에 있다.

- **관련도 기준**: OR 매칭이라 흔한 단어 하나만 맞아도 후보가 되고 limit까지 채워 무관한 글이 섞임. DB에 없는 주제에서도 "결과 없음" 대신 무관한 카드를 반환(시나리오 6) → 순위 품질뿐 아니라 "없으면 없다고 말한다"는 안전장치를 위해서도 필요
- **형태소 분석 일관성**: "동시성"이 문맥에 따라 `동시`와 `동시성`으로 다르게 잘림. 외래어 기술 용어가 잘못 분리됨("시그널링" → `시그널` + `링`, "아웃박스" → `아웃` + `박스`) → 사용자 사전·토큰 정규화 검토
- **1글 = N사례 구조의 순위 불이익**: 하위 문제별로 나뉜 사례는 검색어가 적게 걸려 관련 글이 무관한 글보다 아래로 감(시나리오 2) → 같은 글의 사례를 묶어 올리는 방식 검토
- **비교 대상이 되는 사례**: 질문과 다른 각도에서 관련 있는 사례(시나리오 5의 case_0030)는 점수가 낮음 → 관련도 기준이 이런 사례를 잘라내지 않는지 확인

**중간 결론**

- 상대 점수는 검색어가 짧고 주제가 좁을 때 잘 작동하지만, 여러 주제를 섞은 긴 검색어에서는 점수가 고르게 퍼져 잡음을 거르지 못한다.
- 넓은 주제의 검색어에서는 관련 글이 넓은 점수 범위에 퍼져 상대 점수 기준이 관련 결과를 잘라낸다.
- DB에 없는 주제에서는 1위부터 무관할 수 있어, 상대 점수만으로는 "결과 없음"을 판정할 수 없다. "결과 없음" 판정에는 절대 점수 하한이나 희소 단어 일치 여부가 유력한 후보다.
- 흔한 단어("도입", "서버", "설계") 하나만 맞은 글을 거르는 단어 일치 기준이 좁은 주제, 넓은 주제, 없는 주제 모두에 유효해 보인다.
- 에이전트가 문제 유형·도메인·기술 필터를 쓰면 후보가 크게 줄어 잡음이 거의 사라진다.
