# M1. 수직 슬라이스 (올리브영)

> 상태: **완료** (2026-09-30) · 허브: [docs/README.md](../README.md)

수집이 가장 쉬운 올리브영 한 곳으로 수집 → 추출 → 검색 → MCP 서버까지 끝까지 연결하고, Claude Code에서 직접 써 본다.

## 작업

| 순서 | 작업 | 결과물 |
| --- | --- | --- |
| 1 | 올리브영 피드 수집기, 원문 로컬 캐시, 3년치 필터 | `data/raw/`, 글 메타데이터 |
| 2 | 분류 정의 파일(문제 유형·도메인 초안), 기술 사전 초기 버전 | `taxonomy/` |
| 3 | 추출기: 글 유형 분류 + 사례형·인사이트형 구조화 (Pydantic 스키마, structured output) + 발췌 원문 검증 | `pipeline/extract/` |
| 4 | 올리브영 약 20편 추출 (임시 모델) | `data/entries.jsonl` |

| 6 | MCP 서버: `search`, `get_details`, `aggregate`, `/techblog` prompt | `src/techblog_mcp/` |
| 7 | Claude Code에 연결해 실제 개발 질문으로 사용해 보고, 스키마·도구 설계 피드백 반영 | 피드백 기록 |

## 실사용 테스트 시나리오

에이전트가 **도구 설명만 보고** 스스로 호출을 판단하는지, 결과를 원칙대로 쓰는지 확인한다.

**준비**

- 이 저장소가 아닌 빈 폴더(예: `C:/techblog-test`)에 서버를 등록한다. 이 저장소 안에서는 에이전트가 CLAUDE.md와 코드로 도구의 존재를 이미 알아 판단이 오염된다.
  `claude mcp add techblog -- uv run --directory "C:/Techblog MCP" techblog-mcp`
- 서버 코드를 바꾼 뒤에는 새 세션을 연다. 서버 프로세스와 도구 설명은 세션이 시작될 때 한 번만 읽힌다.

**진행 방법**

- 시나리오마다 **새 세션**을 열고 아래 입력을 그대로 붙여 넣는다. 도구를 쓰라는 말은 덧붙이지 않는다.
- **서버 연결을 확인한 뒤 입력한다.** 서버 기동에 1.4~1.9초가 걸려 세션을 열자마자 입력하면 에이전트가 도구를 볼 수 없다 (시나리오 6 1회차에서 발생).
- 도구 허용 창이 뜨면 "한 번만 허용"을 눌러 호출 순서와 인자가 화면에 남게 한다.
- 도구 호출 화면(캡처)과 답변 전문을 Claude에게 전달한다. Claude가 같은 인자로 도구를 다시 실행해 답변 속 사실을 대조하고, 아래 "사용 피드백"과 [M5 관련도 기준 관찰 기록](M5.md#관련도-기준-관찰-기록)에 결과를 남긴다.

**시나리오마다 확인할 것**

1. 도구를 스스로 호출했는가 (7번대는 호출하지 않았는가)
2. 어떤 인자로 불렀는가: 검색어 길이, 필터, 연 글의 ID. 검색어는 M5 관찰 기록에 쌓는다
3. 답변에 회사명과 원문 링크를 밝혔는가
4. 도구 결과에 없는 내용을 사례처럼 붙이지 않았는가
5. 사례를 참고로 소개하고 사용자 상황과의 차이를 짚었는가, 사례와 자기 제안을 구분했는가
6. 결과가 없거나 적을 때 그 사실을 말했는가
