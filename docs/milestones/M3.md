## 결과 요약

- **추출 구조를 단순화했다.** 정답 검수 중 판단이 자주 갈린 두 가지를 없앴다: 사례·인사이트 구분(→ 추출/제외 + 항목 구조 하나), 주 문제 유형·도메인 하나 고르기(→ 다중 선택). `search`가 핵심이고 집계 편의로 검색 정확도를 낮추지 않는다는 원칙을 기획에 명시했다.
- **대상 글 기준을 다듬었다.** 조직 문화·직무 소개·행사 글, 발표 소개(목차만) 글, 도구 장려 제도 운영기, 팀 경험 없는 개념 글은 제외.
- **평가 체계를 만들었다.** 정답셋 24편(사용자 검수), 자동 지표, gpt-5.5 LLM 채점(6개 항목), LangSmith 트레이싱. 채점기는 원문 대조로 검증했다.
- **모델을 바꿨다.** gpt-5-mini → gpt-5.6-luna로 비용은 약 1/3, 완결성 61% → 78%, 분류 기준 준수와 실행 간 안정성이 크게 좋아졌다.
- 프롬프트는 baseline `d2178d29df58` → 최종 v4 `5bafd9ddcc5d`. M3 평가 API 비용 합계 약 $40 (추출·채점).

## M4로 넘기는 항목

- **전체 재추출**: 1,262편을 `gpt-5.6-luna` medium, 프롬프트 v4로 추출 (Batch API 검토). M1 올리브영 20편(`data/`, gpt-5-mini·옛 프롬프트)도 `--outdated`로 다시 추출. 추정 비용 $5~6 (Batch 약 절반)
- **연결 오류 대비**: 7단계 중 네트워크 끊김으로 run마다 24편씩 실패했다. OpenAI 재시도를 6회로 늘렸고, 실패한 글은 같은 명령을 다시 돌리면 그 글만 추출된다
- **기술 사전 보강**: luna run에서 사전에 없는 이름 133종. 기술 정밀도 55~62%(정답에 없는 언급·교체 기술·브라우저 API까지 넣는 경향)
- **분류 목록 검토**: 공백 후보 2개(JVM·GC 성능 튜닝, 검색 품질·정확도), 도메인 축의 "LLM·AI"·"사내 플랫폼·개발 도구" 성격
- **완결성**: 핵심 사실 대부분이 "일부"만 담김(수치·조건 일부 누락). 검색 결과에서 조건 비교가 부족하면 프롬프트 보강 후보
- **항목 분할 흔들림**: luna도 같은 글을 실행마다 1~3개로 나눔(정답 허용 범위 안). 검색 결과에서 같은 글이 여러 카드로 나오는 영향은 M5에서 관찰
- **경계 글**: 업무 프로세스와 기술 사이 글(우아한형제들 백로그 운영)은 실행마다 추출/제외가 갈림

## 진행 방식

실행 계획 전문은 [.claude/plans/m3-pilot-eval.md](../../.claude/plans/m3-pilot-eval.md)에 있다.

| 항목 | 방식 |
| --- | --- |
| 파일럿 표본 | 블로그마다 시드를 고정해 무작위 10편 (`eval/sample_pilot.py` → `eval/pilot_posts.txt`). 올리브영은 M1 20편 제외 |
| 결과 저장 | 평가용 추출은 `eval/runs/{run}/`에 따로 저장 (`--out-dir`). `data/`는 건드리지 않음 |
| 정답셋 초안 | Claude Code 세션에서 원문을 읽고 작성 → 직접 원문과 대조해 검수. 비교 대상인 OpenAI 모델과 계열이 달라 특정 후보 쪽으로 기울지 않게 함 |
| LLM 채점 | `eval/judge.py` (gpt-5.5). 채점 기준을 프롬프트로 고정해 다시 돌릴 수 있게 함. 채점기 검증은 사람 검수 대신 Claude Code 세션이 원문과 대조 ([추출평가.md](../추출평가.md)) |
| 평가·관측 | LangSmith 도입 (원문 포함 트레이싱, Dataset, Experiment). 사람 검수(Annotation queue)는 쓰지 않기로 함. 결정과 근거는 [기획.md](../기획.md) "평가·관측 도구" 행 |
| 모델 후보 | 가성비 중심: 기준 `gpt-5-mini`(medium, 2회), mini low·high, 저가 `gpt-5.6-luna`, `gpt-5.4-mini`, 상위 `gpt-5.6-terra`. 채점 모델(gpt-5.5) 계열은 제외. luna는 안정성 확인용으로 2회 |

근거가 된 실사용 테스트 기록은 [M1 사용 피드백](M1.md#사용-피드백)에 있다.

- **technologies 품질**: LLM이 개념·클래스 이름(`kafkaTemplate`, "관계형 데이터베이스")을 넣음. 버린 대안(Lua 스크립트)이 technologies에도 들어가는 경우가 있음 → 프롬프트 보강

- **기술 사전 구조**: 기술 집계에 모니터링·알림 도구가 메시지 큐와 섞임(시나리오 4) → 기술에 분류(메시지 브로커, 모니터링, DB 등)를 붙일지. Kafka와 Amazon MSK가 별개로 집계됨 → 기술 간 상하 관계를 둘지
