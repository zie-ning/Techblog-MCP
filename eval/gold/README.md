# 추출 정답셋

M3 추출 평가용 정답 24편(블로그당 3편). 목록은 [../gold_posts.txt](../gold_posts.txt), 형식은 [../gold.py](../gold.py)의 `GoldPost`.

- 초안은 Claude Code 세션에서 원문을 읽고 작성했고, 사람이 원문과 대조해 검수한 파일은 `reviewed: true`로 바꾼다.
- 원문 전체는 넣지 않는다. 요약과 짧은 수치만 넣는다 (`docs/기획.md` "원문 정책").
- 분류 값은 `src/techblog_mcp/taxonomy/`의 목록을 쓴다. 목록이 바뀌면 정답도 함께 고친다.
- 필드별 선택지와 정의는 [REFERENCE.md](REFERENCE.md)(검수 참고표), 글별 정답은 [REVIEW.md](REVIEW.md)(검수표)에서 본다.

## 라벨링 기준

기준은 `docs/기획.md`의 결정(대상 글, 항목 구조, 버린 대안, 기술명 정규화, 분류 목록 조정 기준)을 따른다.

### 추출 여부 (`kind`)

| 값 | 기준 |
| --- | --- |
| 추출 | 다른 팀이 설계·구현 판단에 참고할 기술적 실무 내용이 있다. 겪은 문제와 해결, 기술 선택·도입 근거, 도구·기술 적용 경험과 팁 |
| 제외 | 개념·튜토리얼, 회고·조직 문화·협업 방식·직무 소개·행사 후기·채용, 발표 소개·목차만 있는 글 |

- M3 검수 중 사례·인사이트 구분을 없앴다. 판단이 자주 갈리고(정답 17편 중 5편이 경계) 추출 모델도 흔들려서다.
- 경계 글은 가장 맞는 값을 `kind`에, 맞다고 볼 수 있는 다른 값을 `kind_alternatives`에 넣고 이유를 `notes`에 쓴다.
- 행사·문화 글에 AI 도구나 실무 팁이 일부 나와도 제외한다. 글의 주제가 도구 적용 방법과 결과일 때만 추출.
- 도구 사용을 장려하는 조직 차원의 제도·프로그램 운영기(지원 제도, 참여 규모, 설문 결과 중심)는 AI 도구 도입 글이어도 제외 (예: kakao/762 AI 마일리지).

### 항목 나누기

- 독립적인 문제-해법 쌍마다 항목 하나. 같은 문제의 단계적 해결은 한 항목.
- 팁 모음·도구 활용 경험 글은 항목 하나.
- 사소한 곁가지는 항목으로 만들지 않는다. 대부분 1~3개.
- 항목 수는 정답과 정확히 같지 않아도 된다. 평가에서는 `summary`로 추출 결과의 항목과 대응시킨다.

### 분류

- 문제 유형(1~3개)과 도메인(1~2개)은 다중 선택이다. 해결의 목적 기준(쓴 기술이 아니라 무엇을 풀었나)으로 고른다.
- `problem_types`·`domains`에는 추출 결과에 **꼭 들어가야 할 값**(재현율 기준)을, `acceptable_*`에는 **들어가도 틀리지 않은 값**(정밀도 기준)을 넣는다. 하나의 해결이 여러 문제를 함께 풀었으면 꼭 들어갈 값을 여러 개 둔다.
- 도메인은 그 시스템이 속한 서비스 영역. 개발 도구·사내 공통 플랫폼 자체가 대상이면 "사내 플랫폼·개발 도구", 두 영역에 걸치면 둘 다. "범용"은 다른 도메인이 없을 때만.
- M3 다중 선택 전환 때 기존 주 유형·도메인을 꼭 들어갈 값으로, 허용 답을 허용 값으로 옮겼다. 검수할 때 허용 값 중 꼭 들어가야 할 것은 앞으로 옮긴다.

### 기술과 버린 대안

- `technologies`: 실제로 쓴 제품·라이브러리·프레임워크·서비스. 기술 사전에 있으면 표준 이름, 없으면 흔히 쓰는 이름. 클래스명·일반 개념·사내 시스템 이름·버전은 넣지 않는다. 검토만 하고 버린 기술은 넣지 않는다.
- `rejected_alternatives`: 글에 "검토했지만 이런 이유로 쓰지 않았다"고 명시된 것만. `기술`(제품 자체) / `설계 방식`(패턴, 구현·설정·운영 방법).

### 핵심 사실 (`key_facts`)

추출 결과에 반드시 담겨야 할 것. 완결성 채점(5단계 LLM 채점)의 기준이 된다.

- 원문에 나온 조건: 트래픽·데이터 규모, 지연·가용성 요구, 기존 인프라·팀 제약
- 적용 결과 수치 (예: 처리 시간 n배 단축)
- 핵심 결정과 그 이유
- 항목당 2~5개. 원문에 수치가 없으면 결정과 이유만.
