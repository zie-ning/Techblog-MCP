# PR 작성 규칙

이 문서는 클로드 코드가 이 저장소에서 PR을 작성할 때 참고하는 규칙이다.

## 제목

`<타입>: <작업 요약>` 형식으로 작성한다.

예: `docs: 개발 로드맵 문서 작성`

**타입:**

- `feat`: 새로운 기능
- `fix`: 버그 수정
- `docs`: 문서화
- `style`: 포맷팅
- `refactor`: 코드 리팩토링
- `perf`: 성능 개선
- `test`: 테스트
- `chore`: 빌드/도구
- `ci`: CI 관련 설정 수정에 대한 커밋

## 본문

- 무엇을 왜 바꿨는지를 개조식으로 짧게 쓴다. 관련 마일스톤 문서(`docs/milestones/`)가 있으면 링크한다.
- 테스트·검증을 어떻게 했는지 적는다.

## 병합

- CI(테스트, 린트, 포맷 검사)가 통과한 뒤 병합한다.
- **Merge commit**으로 병합한다. 브랜치의 원자적 커밋과 PR 단위의 경계를 모두 기록에 남기기 위함이다. Squash·Rebase 병합은 쓰지 않는다.
- 병합한 브랜치는 원격과 로컬에서 지운다.
- 병합과 브랜치 삭제는 push와 마찬가지로 사용자가 지시했을 때만 한다.
